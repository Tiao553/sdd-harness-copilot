O Problema

Sem AgentSpec

  • Sem contexto do projeto carregado
  • Qualquer pergunta vai para o mesmo “agente”

Com AgentSpec

  • KB local com padrões do time

Dores reais

Os 5 problemas críticos

  • Contexto perdido — cada nova conversa começa do zero
  • Agente único — mesma abordagem para dbt, Spark, IAM...
  • Zero controle — sem entry/exit gates entre fases
  • Token waste — KB inteiro carregado quando bastava 1 arquivo
  • Audit trail ausente — sem rastreio de quem decidiu o quê

Controle de qualidade

Quality Gates

  • Entry/Exit gates — cada fase exige critérios mínimos para avançar
  • Clarity Score — Define exige pontuação de clareza nos requisitos
  • File Manifest — Design exige manifesto completo com @agents
  • Validate obrigatório — Build → Ship bloqueado sem validação
  • Score ≥ 90 — threshold mínimo + zero findings CRÍTICOS

Fase 3.5

Validate — 4 Juntas

  • Junta de Spec — mapeia cada requisito DEFINE para evidência no código (4 personas: MGR, ARC, ENG, SWE)
  • Junta de Código — qualidade, anti-patterns, type safety, DevOps hygiene (4 personas)
  • Junta de Entrega — compara DESIGN manifest vs code_tree real (2 personas: CMP, GAP)
  • Conselho Final — sumário executivo e readiness assessment (3 personas: JDG, RPT, PRD)
≥ 90
Score para RUNBOOK
0
CRITICAL permitidos

Pipeline de Validação

Contratos do Workflow

Entry → Exit Gates

  • DEFINE input: ideia → output: requisitos + clarity score
  • DESIGN input: DEFINE → output: manifest + @agents
  • BUILD input: DESIGN → output: código + BUILD_REPORT
  • VALIDATE input: tudo → output: score + RUNBOOK/ROADMAP
  • SHIP input: VALIDATE aprovado → output: archive

Regras de bloqueio

Ship é bloqueado
Sem VALIDATION_REPORT aprovado, ship não executa
Score determinístico
Fórmula fixa, sem LLM influenciando nota final
Cascade com Iterate
Mudanças em DEFINE propagam para DESIGN automaticamente

Fase Build

Delegação a Especialistas

  • DESIGN contém @{agent-name} por arquivo
  • Build lê o agent file + KB do especialista
  • Especialista executa sob seus próprios quality gates
  • Evidência registrada no BUILD_REPORT
  • Se quality gate falha, build para imediatamente
